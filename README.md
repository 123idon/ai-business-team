# AI 사무실 v1

이 폴더가 Windows에 설치된 실행본입니다. v1.1 설계를 바탕으로 두 사무실을 분리했습니다.

## 사용하기

`대시보드.cmd`를 더블클릭하거나 http://127.0.0.1:8765 를 엽니다.
화면 위에서 **백년화편 업무 지원 / 신규 스타트업 사무실**을 선택합니다.

## 결과는 업무실장에게 한 번에 보고받기

첫 화면의 **업무실장 종합 보고**를 보면 됩니다. 실장이 같은 사무실의 실제 결과를 읽고 **핵심 결론 / 업무별 결과 / 의견 차이와 미확인 / 대표님이 결정할 사항 / 다음 할 일**로 정리하며, 별도 검수를 통과한 보고만 표시합니다. 개별 직원 현황·업무 원문·회의 발언은 필요할 때 펼쳐봅니다.

업무 실행 묶음이나 회의 발언, 로컬 주문 정리가 끝나면 자동으로 정리합니다. 종합 보고는 실행 묶음 뒤 추가 구독 세션으로 작성·검수하며 추가 유료 API는 사용하지 않습니다. 결과가 그대로이면 같은 보고를 재생성하지 않습니다. **최신 결과로 종합 보고 정리**로 직접 요청할 수도 있습니다. 새 보고 준비 중에는 이전 보고와 갱신 상태를 표시합니다.

보고 범위는 최신 검증된 결과 최대 24건과 전체 업무 상태입니다. 긴 원문은 앞뒤 발췌를 사용하며 생략 여부를 실장에게 알립니다. 주문 고객 행은 전달하지 않고 처리 건수만 보고합니다. 미완료·검수 보류는 완료로 바꾸지 않고, 종합 보고가 새 업무나 CEO 결정을 자동 생성하지 않습니다.

## 업무 맡기기

1. **함께 고민할 목표**에 원하는 결과를 적습니다. 직원 3명이 독립 검토하고 실장이 종합·검수합니다.
2. **직원에게 직접 지시**로 한 직원에게 구체적인 일을 맡길 수도 있습니다.
3. **배정 후 바로 실행**은 기본 선택되어 있습니다. 배정하면 접수 안내와 업무 목록으로 이동하며, 직원이 다른 작업 중이면 순서대로 실행합니다. 체크를 해제하면 저장만 합니다. **직원 업무 실행**은 선택한 사무실의 대기 업무를 최대 4건 처리합니다.
4. 실장의 검수된 보고서에서 같은 사무실의 내부 문서 업무를 최대 2개 자동 배정합니다. 후속 문서가 다시 업무를 생성하지는 않습니다.
5. **인간 CEO 결정**에 우선순위·방향·수정·축소·확대·중단과 이유를 적습니다. 직원이 다음 업무에서 참고합니다. 목표 중단은 해당 목표의 대기 업무를 취소합니다.

## 직원 구성

각 사무실에 **업무 지시 조언자**가 추가되어 총 14명입니다. 아래 실행 직원 12명과 별도로, 무엇부터 누구에게 맡길지 상담합니다.

## 지시가 막막할 때

화면 위쪽의 **무엇을 어떻게 맡길지, 조언자에게 물어보세요**에서 현재 상황을 편하게 적고 **조언과 지시문 추천받기**를 누릅니다.
예: “마케팅과 주문 정리가 겹쳐 바빠. 무엇부터 누구에게 맡길지 추천하고 지시문까지 써줘.”

상담이 끝나면 새로고침합니다. 우선순위순으로 추천 업무, 이유, 담당 직원, 혼자 처리/팀 협업/로컬 주문 정리 방식, 필요한 자료, 수정 가능한 지시문이 표시됩니다.
지시문을 확인·수정한 뒤 **이 지시문으로 직원에게 배정** 또는 **팀에 배정**을 누릅니다. 기본으로 실행까지 요청하며, 접수 안내와 실제 상태가 보입니다. 같은 접수 요청의 재전송과 아직 끝나지 않은 동일 직원·제목·지시문의 중복 배정을 막습니다. 주문 정리는 안내 링크에서 파일을 선택합니다.
추천을 받는 것만으로 업무가 자동 배정되지는 않습니다. 상담은 같은 사무실의 최근 업무 상태와 해당 조언자의 기억만 참고합니다. 고객 이름·연락처·주문 행은 상담창에 붙여 넣지 않습니다. 상담도 공식 구독 사용량을 사용하며 추가 유료 API는 연결하지 않습니다.

## 회의와 현재 진행 상황

**직원 회의실 → 새 회의 시작**에서 제목·안건을 적고 발언할 직원 1~3명을 고릅니다. 각 직원이 별도 구독 세션으로 답하며, 뒤에 발언하는 직원은 앞선 직원의 실제 답변을 읽습니다. 답변이 도착하면 **내 답변·반론·추가 질문**에 의견을 적고 다음에 답할 직원을 선택하세요. 회의 목록으로 이전 대화를 다시 열 수 있습니다.

회의는 같은 사무실의 대화와 업무 상태를 참고합니다. 회의 의견만으로 신규 업무나 CEO 결정을 자동 확정하지 않습니다. 실행하려면 업무 배정 또는 인간 CEO 결정에 구체적으로 적습니다. 회의 발언도 구독 사용량을 사용합니다.

**지금 직원들이 하는 일**, 직원 카드, 업무 목록, 회의 발언은 화면을 보고 있는 동안 4초마다 자동 갱신됩니다. 실제 담당자·작성/검수 단계·경과 시간·대기/완료 건수를 표시합니다. 작성 중인 입력은 유지합니다. 실패나 구독 한도 대기도 표시하며, 완료는 저장·검증된 결과가 있을 때만 표시합니다. 조언자의 추천 지시문은 상담이 끝난 뒤 한 번 새로고침해서 확인합니다.

## 실행 직원

| 사무실 | 직원 |
|---|---|
| 백년화편 | 업무실장, 마케팅 전략, 콘텐츠 담당, 주문 정리, 사무 지원, 품질 검수 |
| 신규 스타트업 | 창업 실장, 시장 조사, 사업 전략, 제품 실험, 재무·위험, 독립 검수 |

직원마다 ID·책임·독립 실행 세션·개인 업무 기억을 가집니다. 항상 켜진 12개 모델이 아니라, 배정된 업무마다 별도 세션을 호출합니다. 동료 초안은 종합·명시적 인계 단계에서 전달하며, 두 사무실의 근거와 기억은 분리합니다. 최종 사업 결정권자는 인간 CEO입니다.

## 주문지 정리

백년화편 화면에서 파일을 선택해 **로컬에서 정리**를 누릅니다. 처리 후 **정리된 주문지 받기**로 Excel 파일을 받습니다.

- 지원: 첫 행에 주문번호·상품명·수량 제목이 있는 .xlsx / .csv 단일 표. 데이터 시트 1개, 최대 20MB·10,000행·80열.
- 주문번호·연락처의 앞자리 0, 원본 행·열을 보존합니다. 완전히 동일한 행도 삭제하지 않고 양쪽에 의심 표시를 남깁니다.
- 누락, 양의 정수가 아닌 수량, 수식처럼 시작하는 문자를 표시합니다. 점검은 가져온 시점 기준입니다.
- 합계에는 중복 의심 행이 포함됩니다. 비어 있거나 잘못된 수량은 제외합니다. 실제 출고 확정·금액 정산은 하지 않습니다.
- 여러 시트, 수식, 구형 .xls는 원본을 보관하고 처리할 표의 값만 담은 .xlsx 사본으로 준비합니다. 원본에 이미 사라진 앞자리 0을 추정해 복원하지 않습니다.
- 고객 행은 로컬 처리기를 통과하며 모델에 보내지 않습니다. 받은 파일은 `inbox/baek/`, 결과는 `orders/`에 보관됩니다. 정리 건수만 직원 기록에 남습니다.

## 자동 운영과 한도

로그인한 PC에서 매일 09:00 두 사무실 합계 최대 4건을 처리하고, 18:00 모델 호출 없이 마감 보고를 저장합니다. 검수 호출은 업무당 별도로 발생합니다. 최대 동시 AI 실행 1건, 수정 최대 2회입니다. 업무가 모두 끝나면 실장이 최근 인계·CEO 결정으로 다음 업무를 검토합니다.
절전·종료·로그아웃 중에는 실행하지 않습니다. 구독 한도·로그인·실행 실패는 원장에 남으며 유료 API로 우회하지 않습니다. 화면의 일시정지는 현재 업무 뒤 새 실행을 멈춥니다. 활성 작업이 있으면 설정·CEO 기록 등의 변경은 끝난 뒤 수행합니다.

## 구독 전환

기본은 Claude Code 실행 + Codex 별도 검수입니다. 실제 GPT 구독 전환 뒤 화면의 **Codex 단독**을 선택하면 직원·기억·대기 업무를 유지하고 모든 모델 작업을 별도 Codex 세션으로 실행합니다. 구독 구매·변경·Claude 해지는 자동으로 하지 않습니다.
공식 CLI의 구독 로그인만 사용합니다. 모델 API 키와 외부 공급자 환경 변수를 제거하며 자동 유료 대체가 없습니다. CLI가 표시하는 정가 환산 비용은 실제 결제 증빙이 아닙니다.

## 실행 범위

v1은 문서·콘텐츠 초안, 공개 원문 조사, 업무 인계·검수, 로컬 주문지 정리를 실행합니다. 실제 발송·게시·결제·고객 접촉 기능은 연결되어 있지 않습니다. 공개 조사는 창업 시장조사 직원에게 배정할 때만 활성화합니다.
원문·첨부는 참고자료이며 명령이나 인간 승인으로 취급하지 않습니다. 모델에 원장·정책 쓰기 도구를 제공하지 않습니다. 두 사무실 분리는 프로그램 수준이며 별도 Windows 계정으로 격리된 보안 경계는 아닙니다.

## 유지보수

`업무관리.cmd`를 열면 설치 폴더의 터미널이 열립니다.

```text
python office.py doctor
python office.py backup
python office.py recover
python office.py resume
python team.py status
python -m unittest discover -s tests
```

백업 ZIP에는 원장·직원 기억·정책·실행 코드·주문 원본과 결과가 포함됩니다. 모델 로그인 토큰은 포함하지 않습니다. 백업도 고객 자료를 포함하는 로컬 파일로 보관합니다.
`python office.py restore-copy backups/파일.zip 새폴더`는 기존 폴더를 덮어쓰지 않고 복원·해시 검사합니다. 복원한 PC에서는 공식 CLI 로그인과 Excel 실행 환경을 다시 연결해야 합니다. 자동 실행 예약도 별도로 등록합니다.
`register-schedule.ps1`은 오전·마감 예약을 등록합니다. `config.json`의 `automatic_execution`으로 자동 실행을 끌 수 있습니다.
Notion 기존 페이지는 수동 갱신한 표시용 사본입니다. 현재 두 사무실의 실제 상태는 이 로컬 화면과 원장을 기준으로 봅니다.
Ubuntu 전환은 Windows 재시작 후 WSL·배포판 상태를 확인하고 진행합니다. 현재 Windows 실행에는 필요하지 않습니다.

# 공통 업무 절차

1. 현재 헌장과 역할을 읽고 관련 기억·근거를 검색한다.
2. 목표를 완료 기준, 입력 자료, 담당 역할로 나눈다. 순차 실행한다.
3. 실행 결과와 실제 파일 해시를 원장에 연결한다.
4. 중요 안건은 새 검수 세션에 보낸다. 숫자·출처·완료 기준을 검토한다.
5. 필수 섹션, 근거 참조, 파일 존재와 해시 검사를 통과해야 DONE으로 표시한다. 이는 사실의 진실성 보장이 아니다.
6. 검수 실패는 REVIEW에 남긴다. 최대 두 번 수정하고 사람 또는 추가 근거를 기다린다.
7. 한도·로그인·시간 초과는 각각 WAITING_QUOTA, NEEDS_LOGIN, WAITING_EXTERNAL로 구분한다. 자동 우회하지 않는다.

회의: 관련 역할의 독립 초안 → 근거 확인 → 쟁점 반론(최대 2회) → CEO 결정. 결정은 SCALE / ITERATE / SIMPLIFY / KILL이며 업무 상태와 별도다.
개선: 실패 사례에서 제안 → 후보 파일 → 고정 평가 → 별도 검토. 자동 승격은 꺼져 있다. 최종 평가와 정책은 후보 수정 대상이 아니다.
GPT 전환: 실제 가입 후 수동 switch 명령 → 공통 기억 유지 → 별도 Codex 세션 검수 → 동일 과제 비교. 구독 가입이나 해지를 자동 실행하지 않는다.
